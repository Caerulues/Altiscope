# 三维高度轨迹：实现与验证（2026-10-02）

## 本次范围

在执行前已有的 22.6–22.16 改造上，补齐后来新增的 **22.10 V4** 。此前只有倾斜 MapKit 相机，轨迹仍是地面 MKPolyline；本次增加真实 XYZ 顶点、透视投影、深度检测和半透明幕帘。既有未提交修改保留。没有改写用户旅程、导入格式或原始传感器数据，没有提交或发布。

## 已实现的行为

- **零平面固定为 z=0** ，高度以 MSL 米计算，统一倍率 **1** 。不以起点或最低点归零；负高度留在零平面以下，点选时明确显示。参考平面用于展示，不模拟地形/建筑遮挡，不能把轨迹与底图关系用于净空判断。
- 有效高度构成彩色主线，并连接同一经纬度的零平面投影形成半透明幕帘。高度颜色与二维地图共用 `RouteAltitudeStyle`；估计段使用虚线与更淡的填充。透明三角形按相机深度排序；主线使用深度缓冲。
- 缺失高度、明确未知的高度基准、暂停及定位缺口不补造高度，不跨段生成幕帘。正负高度交叉处在零面切分三角形，避免扭曲四边形。二维灰线保留未知高度的平面位置。
- 三维相机随底图旋转、缩放、平移及视图尺寸更新。全览考虑高度，并保留倾角；实时跟随为高处点保留相机高度。切回二维恢复原有平面轨迹。
- 点选三维主线或二维投影读取高度；沿用图表的 `chartUnits` 偏好。公制/航空单位切换只更新文本。未知高度显示缺失状态，估计值与普通记录值区分。
- 显示抽样保留分段、缺失边界、峰谷及明显的平面转折；原始数组不变。直线路段不为零偏差增加额外显示点。
- 继续使用 Apple MapKit。当前位置、地面线和立体几何在显示边界使用同一 `DisplayCoordinate.mapKitInput`，当前合同保持 WGS84；没有新增 GCJ02 偏移。

（实现来源：`Sources/AltiscopeCore/RouteScene.swift`、`RouteDisplay.swift`、`App/Maps/RouteAltitudeRenderer.swift`、`RouteMapView.swift`、`App/Views/TrackerView.swift`。）

## 相机模型与边界

### 系统接口的已知能力

MapKit 的公开坐标转屏幕接口只接收经纬度；相机提供位置、倾角与朝向。平面 satellite/hybrid 类型会把倾角限制为零。Apple 在 WWDC22 说明：非 Directions 的自定义覆盖层会使真实地形地图转为平面显示。

（来源：[坐标转屏幕接口](https://developer.apple.com/documentation/mapkit/mkmapview/convert(_:topointto:))、[MKMapCamera](https://developer.apple.com/documentation/mapkit/mkmapcamera)、[pitch](https://developer.apple.com/documentation/mapkit/mkmapcamera/pitch)、[WWDC22: What’s new in MapKit](https://developer.apple.com/videos/play/wwdc2022/10035/)。）

### 本项目采用的推导与保护

`RouteProjection` 从四组公开的地面坐标/屏幕坐标拟合局部平面单应矩阵，再按等尺度正交轴、屏幕中心主点的针孔相机模型恢复竖直轴。高度会改变齐次深度和透视缩放；没有按屏幕竖直方向平移二维线段。数学模型属于本项目实现，**不是 Apple 保证的内部相机参数接口** 。

几何以轨迹锚点建立东/南/高度坐标，水平坐标由局部 Mercator 米制转换而来，竖直轴统一使用米。地图与自定义 Metal 层逐帧同步。每次校准检查额外地面参考点，并检查可见路线的投影误差；误差超过设计阈值（参考点 **1.5 pt** 、可见轨迹 **2 pt** ）、非有限参数、过高纬度/倾角、地球视图或无可用渲染设备时，显示有原因的 **2D 回退** 。这些误差阈值是显示校验参数，不是 GPS 精度指标。

普通地图显式采用平面高程；卫星三维使用可倾斜的 imagery 配置，始终保留原生自定义地面覆盖层来关闭地形起伏，单点轨迹也有零长度覆盖层。恢复相机时保留倾角，避免切换底图或全览后回到俯视。MapKit 仍负责底图、原生手势、位置标记及法律署名，Metal 层不接收触摸。

当前纬度保护为地图中心绝对纬度小于 **80°** 、倾角小于 **75°** 。世界尺度/极区可能回退二维；没有宣称支持全球曲面上任意相机的精确高度渲染。幕帘使用透明参考面，不提供地形遮挡或航空导航精度。

## 实际验证

### 自动化与构建

- 修改前基线：**31 项 XCTest、0 失败** 。本次最终核心回归：**40 项 XCTest、0 失败** ，其中新增 **9 项** 三维相关测试。
- 新测试覆盖绝对高度、零/负高度、零交叉、未知基准与高度、暂停、日期变更线、估计来源、相机后方裁切，以及 **20,000 点** 盘旋轨迹的显示抽样。
- 透视测试使用 **100 组** 已知相机组合（5 个倾角、5 个朝向、2 个距离、2 个视口），比较零/正/负高度的三维投影与独立生成的相机观测。
- 原有直线抽样测试曾发现新增转折逻辑保留过多点；修复为只保留有明显偏离的转折，原测试未经放宽，最终完整回归通过。
- 模拟器 Debug 与未签名 iOS 设备 Release 构建通过。未签名设备构建不代表真机安装或传感器验收。仅有系统 AppIntents 元数据跳过提示，没有 Swift 编译错误。
- 工程生成器包含 Metal/MetalKit 系统框架与新增源码，不新增第三方依赖。生成结果再次生成保持一致。

（证据：`Validation/2026-10-02-3d/` 下的测试和构建日志；`Tests/AltiscopeCoreTests/RouteSceneTests.swift`。）

### 模拟器界面

使用专用 **iOS 18.6 iPad / iPhone** 模拟器，所有路线均为明确标记的程序生成样例，不是真实旅程。

- iPad 横屏与 iPhone 竖屏实际显示爬升、等高、下降、盘旋的主线和幕帘；最高值 **12,000 m** 。未知高度和暂停处可见断口，估计段较淡且虚线。
- 点选同一高处样本，航空单位显示 **39,370 ft** ，切换公制后显示 **12.000 km** ，几何保持不变。
- iPhone 折叠信息面板后地图扩展；双击缩放后底图与三维几何同时更新；二维/三维切换保留同一条示例轨迹。
- 普通/卫星切换实际运行。发现平面卫星模式限制倾角后改用可倾斜配置，并补充全览保留倾角的处理。
- **自动拖动没有产生可确认的平移** ，因此不把此次工具操作记为拖动/旋转/多点触控全部通过。实体指针、VoiceOver、大字体、多窗口分屏、极区和大量真实日志仍需人工/真机验收。

### 性能记录的含义

Debug 验收样例输出 **180 帧** 的模拟器绘制回调与 CPU 提交耗时汇总，原始 JSON 保存在本次验证目录。目标刷新率 **30** ；iPad 的一轮记录约 **29.82 次回调/秒** ，平均 CPU 提交 **1.13 ms** ，最高 **3.69 ms** ，场景包含 **236 个** 有效高度顶点和 **468 个** 幕帘三角形。

这些是模拟器回调与 CPU 处理数据，**不是设备 GPU 帧率、端到端流畅度或能耗测量** ，也不能外推为 20,000 点真实实时渲染性能。长记录的绘制成本、后台耗电和真实设备磁/惯导误差仍未验收。

## 复现入口

Debug 构建可使用启动参数 `--demo-altitude`；打开轨迹页后切换 3D。该样例包含零高度、爬升、平飞、下降、盘旋、负高度、未知高度、估计段和暂停，不进入本地日志。只在显式使用该参数时输出临时性能汇总；Release 不包含这个入口。

```sh
swift test
python3 Scripts/generate_project.py
xcodebuild -project Altiscope.xcodeproj -scheme Altiscope \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```
